# Task: Implement F1 — Fixed Short Punctuation Filler Before `Answer:` for `score`

## Objective

Create F1 as a controlled derivative of the frozen F0 branch.

F0 is the current S1 score formulation:

```text
score primitive
letters
single evaluation
no rotation
no few-shot
no filler
```

F1 must keep all F0 behavior unchanged except for one experimental variable:

> Insert a short fixed punctuation filler immediately before the final `Answer:` anchor.

The initial target is approximately 16 tokenizer tokens of filler.

The purpose is to test whether a small amount of pre-answer filler improves next-token score classification quality for the small Bonsai model without materially increasing latency.

Do not introduce any other formulation changes in this task.

---

# Branch relationship

Treat:

```text
F0 = frozen S1 baseline
```

and:

```text
F1 = F0 + fixed short filler before Answer:
```

F1 should be easy to diff against F0.

Do not refactor unrelated code unless necessary.

---

# Experimental hypothesis

The hypothesis is:

> A short neutral punctuation sequence before the final answer anchor may alter the immediate hidden-state / next-token context in a way that improves candidate-letter discrimination.

This is an empirical experiment.

Do not assume filler necessarily improves reasoning.

Do not describe filler internally as chain-of-thought or hidden reasoning.

The experiment measures whether the final candidate logits improve.

---

# Exact insertion position

Filler must be inserted immediately before the final answer anchor.

F0 conceptually:

```text
State:
...

Question:
...

Possible answers (ordered from lowest to highest):
A: ...
B: ...
C: ...
D: ...

Answer:
```

F1:

```text
State:
...

Question:
...

Possible answers (ordered from lowest to highest):
A: ...
B: ...
C: ...
D: ...

{filler}
Answer:
```

Do not insert filler:

- inside the state;
- inside the question;
- between score options;
- after the `Answer:` anchor;
- after the assistant answer prefix;
- between candidate labels and descriptions.

The only intended variable is the pre-`Answer:` filler.

---

# Filler type

Use neutral punctuation only in F1.

Preferred initial filler family:

```text
.
```

repeated in a form that produces approximately 16 actual tokenizer tokens.

Do not use semantic words such as:

```text
think
wait
consider
reason
step
```

Do not use numbers or letters in F1, because they may interfere directly with score candidate semantics.

Do not use random filler.

F1 must be deterministic.

---

# Important: target tokenizer tokens, not characters

The experiment target is approximately:

```text
16 filler tokens
```

not:

```text
16 periods
```

These are not necessarily equivalent.

Before finalizing the filler string:

1. tokenize candidate filler forms with the active Bonsai tokenizer;
2. measure the actual token count;
3. choose a deterministic punctuation string whose filler portion is as close as practical to 16 tokens.

Record:

```text
filler_text
filler_character_count
filler_token_count
filler_token_ids
```

in diagnostics.

Do not assume repeated punctuation tokenizes one character per token.

# Reference implementation

Implement F1 as a simple prompt-strategy variation.

Conceptually:

```text
build F0 prompt content
append filler
append existing Answer anchor
evaluate once
extract candidate logits
```

Do not add extra model evaluations.

For F1:

```text
evaluations per item = 1
```

This is one of the main advantages of the filler experiment over rotation ensembles.

# Margin gain

Define:

```text

    signed_margin_F1
    - signed_margin_F0
```

Report:

```text

improved margin count
degraded margin count
```

This is especially useful when F0 and F1 have identical accuracy.

---

# Expected-score error change

Define:

```text
error_F0 =
    abs(expected_score_F0 - ground_truth)

error_F1 =
    abs(expected_score_F1 - ground_truth)

change =
    error_F1 - error_F0
```

Interpretation:

```text
negative = F1 improved
positive = F1 degraded
```

Report:

```text
mean change
median change
improved count
degraded count
unchanged count
```

---

# Ground-truth probability change

For each labeled item:

```text
p_gain =
    P_F1(ground_truth)
    - P_F0(ground_truth)
```

Report:

```text
mean p_gain
median p_gain
improved count
degraded count
```

This helps distinguish stronger correct-class evidence even when argmax does not change.
