# Task: Implement S2 — Ordinal Letter-Label Rotation Ensemble for `score`

## Objective

Implement S2 for the `score` primitive.

S2 builds on S1.

S1 uses neutral letter labels:

```text
A -> semantic level 0
B -> semantic level 1
C -> semantic level 2
D -> semantic level 3
```

S2 should preserve the same ordinal semantic order but rotate which output letter is bound to each semantic level.

The goal is to reduce candidate-token bias while preserving ordinal score semantics.

The key rule is:

> Rotate labels, not semantic score order.

---

# Motivation

S1 suggests that this model performs better on score tasks with letters than with digits, especially on harder examples.

However, the letter candidates themselves have strong and unequal content-free priors.

For example, candidate token `A` may be intrinsically preferred over `B`, `C`, or `D`.

S2 should test whether averaging across multiple letter-to-level bindings can reduce that token bias.

---

# Critical distinction from E2

Do not implement S2 as a semantic-option rotation.

For `choice`, E2 may rotate semantic options through candidate positions.

For ordinal `score`, semantic ordering must remain fixed.

Incorrect approach:

```text
Run 0:
A: lowest
B: low
C: high
D: highest

Run 1:
A: low
B: high
C: highest
D: lowest
```

This changes semantic display order and destroys ordinal structure.

Do not do this.

---

# Correct S2 behavior

Semantic score descriptions must always remain ordered from lowest to highest.

Only the letter attached to each semantic level changes.

For four score levels:

## Rotation 0

```text
A: level 0 / lowest
B: level 1
C: level 2
D: level 3 / highest
```

## Rotation 1

```text
B: level 0 / lowest
C: level 1
D: level 2
A: level 3 / highest
```

## Rotation 2

```text
C: level 0 / lowest
D: level 1
A: level 2
B: level 3 / highest
```

## Rotation 3

```text
D: level 0 / lowest
A: level 1
B: level 2
C: level 3 / highest
```

The visible semantic descriptions must remain:

```text
level 0
level 1
level 2
level 3
```

in that order for every rotation.

Only their output labels rotate.

---

# Rotation definition

For `N` semantic score levels indexed:

```text
0, 1, 2, ..., N-1
```

define rotation `r` so semantic level `i` receives candidate label:

```text
label_index = (i + r) mod N
```

where:

```text
label 0 = A
label 1 = B
label 2 = C
...
```

Keep both mappings explicitly:

```text
semantic_level -> candidate_label
candidate_label -> semantic_level
```

Do not reconstruct semantic meaning from prompt text after inference.

---

# Prompt invariant

All rotations must preserve:

```text
state
question
semantic descriptions
semantic description order
instruction wording
answer anchor
assistant suffix
```

Only the letter labels change.

Conceptually:

```text
Possible answers (ordered from lowest to highest):
B: Very poor
C: Poor
D: Good
A: Excellent

Answer:
```

This is valid because the semantic descriptions remain ordered from lowest to highest.

The fact that labels are not alphabetically ordered is intentional.

---

# Do not sort by candidate label

This is critical.

Do not accidentally reorder prompt lines into:

```text
A: Excellent
B: Very poor
C: Poor
D: Good
```

merely because candidate labels sort alphabetically.

Prompt line order must follow semantic score level.

Always iterate in semantic-level order.

---

# Candidate token validation

Use S1 letter tokens.

For all candidate labels required by the score scale:

```text
A
B
C
D
...
```

verify:

- each is exactly one token;
- token IDs are unique;
- the token form corresponds to the actual answer context.

Fail clearly if any candidate is invalid.

Do not fall back silently to digits.

# Reference execution algorithm

For each score request with `N` levels:

```text
for r in 0 .. N-1:
    create rotation-specific semantic-level -> letter mapping

    build prompt in semantic level order

    evaluate prompt

    extract candidate-letter logits

    optionally apply candidate prior correction

    remap letter logits back to semantic score levels

    store semantic logits for this rotation

aggregate semantic logits across rotations

apply score temperature

softmax

compute:
    predicted discrete score
    expected score
```

The sequential implementation is the correctness reference path.

---

# Semantic remapping

Example for four levels.

Rotation 1:

```text
semantic level 0 -> B
semantic level 1 -> C
semantic level 2 -> D
semantic level 3 -> A
```

Suppose model logits are:

```text
A = 4.0
B = 1.0
C = 2.0
D = 3.0
```

The semantic logits must become:

```text
level 0 = 1.0
level 1 = 2.0
level 2 = 3.0
level 3 = 4.0
```

Aggregation must occur only after this remapping.

---

# Primary ensemble aggregation

For each semantic level `i`:

```text
S_ensemble(i) =
    mean_r S_r(i)
```

where `S_r(i)` is the semantic-level logit after remapping rotation `r`.

Then:

```text
P(level_i) =
    softmax(S_ensemble / T_score)
```

if temperature calibration is enabled.

Without calibration:

```text
P(level_i) =
    softmax(S_ensemble)
```

---

# Do not average candidate-letter logits directly

Incorrect:

```text
mean(logit_A across rotations)
```

because `A` represents a different semantic level in each rotation.

Correct:

```text
candidate logits
    ↓
semantic remapping
    ↓
mean semantic logits
```

---

# Do not average expected scores per rotation as the primary method

Do not define S2 primarily as:

```text
mean(expected_score_rotation_0,
     expected_score_rotation_1,
     ...)
```

This loses information.

Preferred:

```text
aggregate semantic logits
→ one final probability distribution
→ expected score
```

Per-rotation expected scores may be retained as diagnostics.

---

# Prior correction

If prior correction is available, apply it in candidate-token space before semantic remapping.

For candidate `c`:

```text
corrected_logit_c =
    raw_logit_c
    - alpha_score * prior_logit_c
```

Then:

```text
candidate letter
→ semantic level
```

Then ensemble.

This is important because the bias being corrected belongs to the letter token.

---

# Temperature scaling

Preferred order:

```text
raw candidate logits
    ↓
optional prior correction
    ↓
semantic remapping
    ↓
mean semantic logits across rotations
    ↓
T_score
    ↓
softmax
```

Do not independently calibrate each rotation unless implemented separately as a research diagnostic.

---

# Expected score

After obtaining final semantic probabilities:

```text
expected_score =
    sum_i i * P(level_i)
```

This remains identical in meaning to S0 and S1.

Candidate labels must have no effect on the numeric score calculation.

---

# Discrete prediction

Final discrete score:

```text
predicted_level =
    argmax_i P(level_i)
```

Also return or record:

```text
expected_score
```

as before.

For every generated prompt, verify descriptions appear in semantic order:

```text
level 0
level 1
level 2
level 3
```

regardless of labels.

This is mandatory.

---

## 3. Position/letter-bias cancellation

Construct synthetic logits where the model always prefers letter `A`.

Example every run:

```text
A = 5
B = 1
C = 1
D = 1
```

Because every semantic level is mapped to `A` exactly once, the candidate-letter bias should be symmetrically distributed across semantic levels after full rotation averaging.

Final semantic logits should become equal or approximately equal.

This is the key S2 synthetic test.

---

## 4. Semantic ordinal evidence survives rotation

Construct logits so semantic level 2 is strongest in every rotation even though its letter changes.

Verify S2 selects semantic level 2.

---

## 5. Expected score

---

## 6. Prior correction

## 7. No semantic permutation

# Calibration handling

Be careful when interpreting S1 vs S2 calibration.

If no calibration artifact is applied:

```text
T = 1
```

report raw metrics directly.

If fitting calibration later, fit S1 and S2 independently using tuning data.

Do not assume a temperature fitted for S1 is valid for S2.

The ensemble changes the semantic logit distribution.

---

# Decision criteria

S2 is a strong adoption candidate if it:

1. preserves or improves S1 accuracy;
2. preserves or improves MAE;
3. preserves or improves expected-score MAE;
4. preserves or improves QWK;
5. improves S1 NLL / Brier / ECE, especially where fixed letters are poorly calibrated;
6. improves lower-tail margins;
7. does not introduce excessive large ordinal errors;
8. provides enough quality gain to justify its inference cost.

Do not judge S2 from accuracy alone.
