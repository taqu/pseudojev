# Test data

## `golden_r4.jsonl` — release regression references

24 fixed tasks (8 choice, 8 noul, 8 score) with the predictions that the frozen R4 policy
`B_task_only@A_latency` produced for them in the R4 held-out evaluation run. The release candidate
must reproduce these predictions exactly (`test_golden_regression`).

Each line holds:

- `input` — the task as a pjev decision request: `type`, `state` (the text shown to the model;
  structured states are compact JSON), `question`, `domain`, `family`, and `options` as
  `[key, description]` pairs in candidate order (noul: `false`, `true`).
- `expected.strategy` — `nearest_2shot` (choice), `nearest_1shot` (noul) or `knn_5` (score).
- `expected.prediction_index` / `prediction_key` — the selected candidate.
- LLM strategies: `demonstration_ids` (exemplar IDs in prompt order), `prompt_tokens`, `logits`.
- kNN: `neighbour_ids`, `neighbour_labels`, `neighbour_hamming` (top 5, rank order) and
  `vote_shares` (normalised vote weight per level).
- `tags` — why the case was selected, e.g. `topk_rank1_differs_from_r1` (the top-10 search ranks a
  different exemplar first than R1's top-1 search; pins the neighbour-list rule),
  `llm_departs_from_nearest_label`, `weighted_vote_differs_from_uniform`, `string_state`.

`ground_truth_index` is informational; the regression compares predictions, not correctness.
