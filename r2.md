# Task: Implement R2 — Similarity-Gated Retrieved 1-Shot Inference

## 1. Objective

Implement R2, the similarity-gated retrieval experiment in the pjev adaptive retrieval roadmap.

R2 extends the existing R1 experiment by adding exactly one decision rule:

**Use retrieved 1-shot inference only when the Top-1 exemplar similarity meets a configurable threshold. Otherwise, return the original S1 zero-shot prediction.**

The goal is to determine whether semantic similarity can identify cases where retrieval is useful and avoid cases where retrieval causes regressions.

Existing infrastructure includes:

- S1 zero-shot inference
- R0 semantic retrieval evaluation
- R1 always-1-shot evaluation
- SQLite + sqlite-vec exemplar database
- Nomic embedding model
- LZ4-compressed exemplar payloads
- xxHash64 example and group identifiers

Relevant paths:

```text
models/nomic-embed-text-v1.5.gguf
models/exsamplar.db
```

Other exemplar databases may exist, including one built from OpenJevData-140k.

Inspect actual repository paths before implementation.

Do not rebuild or overwrite any exemplar database.

**R2 must isolate the effect of the similarity gate. Do not modify retrieval ranking, prompt construction, or inference behavior.**

## 2. Experimental conditions

Evaluate three conditions on the same examples.

### S1 — Zero-shot baseline

The existing inference implementation without retrieved demonstrations.

### R1 — Always 1-shot

The existing R1 implementation that uses the nearest compatible exemplar whenever one is available.

### R2 — Similarity-gated 1-shot

Use the R1 prediction only when:

```cpp
similarity >= threshold
```

Otherwise, use the S1 prediction.

Conceptually:

```cpp
auto s1 = run_zero_shot(query);

auto retrieval = retrieve_top1(query);

if (!retrieval.has_value()) {
    return s1;
}

if (retrieval->similarity < threshold) {
    return s1;
}

return run_one_shot(query, retrieval->exemplar);
```

This is illustrative pseudocode.

Reuse the existing infrastructure rather than implementing independent inference paths.

Do not add uncertainty-based gating in R2.

That belongs to R3.

## 4. Two-stage implementation

Implement R2 in two separate stages.

### Stage A — Offline threshold evaluation

This is the first priority.

Use existing paired S1/R1 predictions and Top-1 retrieval similarities to simulate R2 at different thresholds.

No LLM inference should be necessary if all required predictions are available.

For each example:

```python
if top1_similarity >= threshold:
    prediction = r1_prediction
else:
    prediction = s1_prediction
```

Calculate R2 accuracy for every threshold.

This allows threshold analysis at very low computational cost.

### Stage B — Online gated inference

After the offline implementation is validated, add a runtime-equivalent gated inference mode.

It must:

1. Run S1.
2. Obtain the Top-1 exemplar similarity.
3. Compare similarity against the configured threshold.
4. Run R1 inference only if the gate activates.
5. Otherwise return S1 directly.

The online implementation must reproduce offline R2 predictions for the same query set, model configuration, and threshold.

Do not perform the R1 inference pass when the similarity gate rejects retrieval.

## 6. Similarity calculation

Use the similarity metric already established in R0 and R1.

If the database uses cosine distance:

```text
cosine_similarity = 1.0 - cosine_distance
```

Verify the actual installed sqlite-vec configuration.

Do not assume all vector distance metrics use this transformation.

Use full-precision floating-point similarity values for threshold decisions.

Round only for display.

### Threshold comparison

Use:

```cpp
similarity >= threshold
```

as the activation rule.

Equality activates R1.

Do not silently change the comparison to a strict greater-than operation.

Reject NaN, infinity, or otherwise invalid similarity values.

Handle missing retrieval results explicitly.

For a query with no eligible exemplar, R2 must use S1 and record that retrieval was unavailable.

## 7. Threshold sweep

Implement a configurable offline threshold sweep.

Suggested default:

```text
Thresholds:
  0.00
  0.05
  0.10
  ...
  0.95
  1.00
```

Also support a more precise analysis based on observed similarity values.

Because R2 decisions change only when the threshold crosses an observed similarity value, an exact empirical sweep can identify all distinct activation patterns without relying on a coarse grid.

Implement at least:

- Configurable fixed-grid sweep
- Exact or quantile-based diagnostic sweep
- Per-kind reporting

Do not round similarities before comparing them with thresholds.

Include two explicit endpoint baselines:

**All eligible R1:** activates every example with an available exemplar, independently of the numerical similarity range.

**All S1:** never activates retrieval.

These endpoints should be represented explicitly rather than assuming a particular threshold always reproduces them.

The offline implementation must agree with the observed S1 and R1 baselines at these endpoints.

## 8. Threshold selection and data separation

This is critical.

Threshold optimization must not use the final evaluation set.

Use a three-part experimental protocol where the available data permits it:

```text
Training exemplar bank
        |
        v
Calibration / tuning split
        |
        v
Select threshold
        |
        v
Freeze threshold
        |
        v
Held-out validation evaluation
```

Prefer an official calibration split if it exists and is independent of the exemplar bank.

Inspect the actual repository dataset organization.

Do not assume that every dataset includes a calibration split.

If no dedicated calibration split is available, create a deterministic, group-disjoint tuning/evaluation partition from an authorized validation dataset, clearly labeling it as an internal experiment.

Do not split related counterfactual variants across tuning and evaluation.

Prefer source-family or template-level partitioning where the metadata supports it.

Do not use the final test or OOD dataset for threshold tuning.

### Recommended selection objective

Select the threshold that maximizes paired accuracy on the tuning split:

```text
R2 accuracy = S1 accuracy + (rescue - harm) / N
```

Here, rescue and harm count only cases where the gate activates.

Avoid choosing a threshold based only on average similarity.

Similarity alone is not the target metric.

### Tie-breaking

If multiple thresholds achieve the same accuracy, prefer the threshold with the lower activation rate.

This favors lower inference cost when accuracy is equal.

Define this policy before examining final evaluation results.

### Overfitting safeguards

Report:

- Tuning sample size
- Selected threshold
- Tuning accuracy
- Tuning activation rate
- Held-out accuracy
- Held-out activation rate

Do not repeatedly adjust the selection rule after examining held-out results.

Do not claim that a threshold generalizes merely because it performs well on the same dataset used to select it.
