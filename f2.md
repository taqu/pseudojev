# Task: Implement F2 — Prior-Corrected F1 for `score`

## Objective

Create F2 as a controlled derivative of F1.

The branch relationship is:

```text
F0:
S1 letters baseline
single pass
no filler
no prior correction

F1:
F0
+ fixed 16-token punctuation filler before Answer:
no prior correction

F2:
F1
+ candidate prior correction
```

F2 must preserve the exact F1 filler, prompt structure, candidate mapping, and single-pass inference behavior.

The only intended experimental change from F1 is:

> Correct the candidate logits using content-free candidate priors measured under the F1 prompt configuration.

The purpose is to test whether F1 failed primarily because the punctuation filler introduced a large candidate-token bias rather than because the filler itself destroyed useful semantic information.

---

# Motivation

F1 produced mixed behavior.

On the original score split:

```text
accuracy:
F0 0.6667
F1 0.7500

MAE:
F0 0.4167
F1 0.3333

QWK:
F0 0.8174
F1 0.8333
```

but calibration and margins degraded.

On the hard split, F1 clearly regressed.

Diagnostics showed that the 16-token filler substantially changed content-free candidate priors.

For four score levels, the observed F1 shifts were approximately:

```text
A: +1.223
B: +1.634
C: +1.699
D: +2.196
```

The highest score label `D` received the largest positive shift.

This creates the hypothesis:

> F1 may contain some useful prompt-state effect, but its raw logits are contaminated by filler-induced letter-token prior bias.

F2 tests that hypothesis directly.

Do not modify the filler in F2.

Use exactly the same frozen filler as F1:

```text

```

```text

```

```text

```

F2 is not a filler-length experiment.

# Content-free priors

Measure content-free candidate priors using the F1 prompt configuration.

This is mandatory.

The prior prompt must include:

```text
the same score PromptStrategy
the same candidate scheme
the same number of levels
the same 16-token filler
the same Answer: anchor
```

while removing or neutralizing task-specific semantic content according to the project's existing blank-prior procedure.

Do not use F0 priors for F2.

Filler changes the candidate distribution, so F2 requires F1-compatible priors.

---

# Prior compatibility

Priors must be keyed by at least:

```text
model identifier / hash
primitive = score

number of score levels

filler configuration
answer anchor
candidate token IDs
```

A prior measured without filler must not be silently reused for F2.

Fail clearly on incompatible metadata.

---

# Prior correction formula

Use:

```text
corrected_logit_i =
    raw_logit_i
    - alpha * prior_logit_i
```

where:

```text
alpha >= 0
```

For the simplest initial F2 reference implementation:

```text
alpha = 1.0
```

must be supported explicitly.

Also make `alpha` configurable so tuning can be performed later without changing inference code.

Do not hard-code `1.0` deep inside DecisionEngine.

---

# Important: preserve raw logits

F2 must retain both:


Do not overwrite the raw logits.

Per candidate, diagnostics should make it possible to inspect:

```text

```

# Probability path

F2 decision flow should be:

```text
F1 prompt
    ↓
raw A/B/C/D logits
    ↓
subtract alpha * F1-compatible prior logits
    ↓
corrected semantic logits
    ↓
softmax
    ↓
score probabilities
    ↓
argmax
expected score
```

For the first F2 experiment:

```text
temperature = 1.0
```

unless the branch already has an independently frozen calibration policy.

Do not simultaneously tune temperature during the first prior-correction comparison.

We want to isolate prior correction first.



This is important.

Changing alpha is a post-logit transformation and must not trigger repeated model evaluation.

# Performance

F2 must remain:

```text

```

The model-evaluation cost should therefore be essentially identical to F1.

Report:


Prior logits should be precomputed / cached per compatible configuration rather than recomputed for every request.
