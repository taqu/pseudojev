# Additional R5 Requirement — Default Calibration Loading

## Objective

Load `models/calibration.json` by default during production initialization and apply its calibration settings to inference results.

Integrate calibration into the existing production inference pipeline without changing the selected task-aware routing policy.

## 1. Default Configuration

Use the following default path:

`models/calibration.json`

Load the file automatically during application initialization.

Allow the path to be overridden through the project's existing configuration or CLI mechanisms.

Do not require users to explicitly enable calibration when the default file is available.

Parse the existing JSON schema without modifying it.

The supplied calibration file uses:

- `version`: 1
- `method`: `temperature`
- `formulation.candidate_scheme`: `natural`
- `formulation.layout`: `auto`
- `formulation.prior_correction`: `true`
- Task-specific temperature and prior-alpha parameters

Preserve the parameter values exactly as stored in the JSON.

Do not round, clamp, normalize, or replace them with hardcoded defaults.

## 2. Calibration Application

Apply calibration to inference strategies that produce candidate logits:

- Choice: Nearest 2-shot
- Noul: Nearest 1-shot
- Zero-shot fallback for all task kinds

Use the project's existing calibration implementation and mathematical conventions.

Preserve the established order of prior correction and temperature scaling.

Do not independently implement a different calibration formula.

### Score kNN-5

Score normally uses similarity-weighted kNN classification without LLM inference.

Do not apply LLM temperature scaling or prior-logit correction directly to kNN voting weights.

The existing `score_temperature` and `score_prior_alpha` parameters apply only when Score uses an LLM-based inference path, including zero-shot fallback.

Do not introduce a new kNN calibration algorithm.

## 3. Formulation Compatibility

The calibration file specifies:

`candidate_scheme = natural`

The R4 experimental configuration used:

`candidate_scheme = letters`

These formulations must not be treated as interchangeable.

Inspect the existing production inference implementation and calibration logic.

Ensure that calibration is applied only to a compatible candidate-logit formulation.

If the calibration formulation requires `natural`, preserve that requirement rather than silently applying parameters trained for `natural` to `letters`.

Do not silently change the validated R4 prompt formulation.

If the requested default calibration cannot be safely applied to the selected release routing configuration, report the incompatibility explicitly.

Do not claim that calibrated behaviour reproduces the R4 reference accuracy.

## 4. Initialization and Error Handling

Load and validate calibration once during initialization.

Validate:

- Supported schema version
- Supported calibration method
- Required formulation fields
- Required task-specific parameters
- Finite numeric values
- Strictly positive temperatures
- Compatibility with the active inference formulation

Use the following policy:

- Missing calibration file: continue without calibration and emit a clear warning.
- Valid calibration file: enable calibration automatically.
- Malformed or unsupported calibration file: report a configuration error.
- Incompatible candidate formulation: report an explicit compatibility error; do not silently apply incompatible parameters.

Do not silently ignore invalid calibration settings.

Avoid repeated JSON parsing during individual inference requests.

## 5. Runtime Behaviour

Maintain the existing task-aware routing:

| Task | Primary inference | Calibration |
|---|---|---|
| Choice | Nearest 2-shot | Apply if compatible |
| Noul | Nearest 1-shot | Apply if compatible |
| Score | Weighted kNN-5 | Not applied to kNN voting |
| Zero-shot fallback | S1 LLM inference | Apply task-specific calibration if compatible |

Preserve the existing output schema.

If the API exposes calibrated probabilities, ensure they are generated consistently with the existing calibration implementation.

Do not change the semantic meaning of returned scores.

## 6. Regression Tests

Add tests verifying:

1. The default calibration path is loaded automatically.
2. A custom calibration path overrides the default.
3. Each task kind uses its corresponding parameters.
4. The exact supplied parameter values are preserved.
5. Prior correction and temperature scaling follow the existing implementation.
6. Score kNN-5 voting remains unchanged.
7. Score zero-shot fallback uses the Score LLM calibration parameters.
8. Missing calibration files produce the documented warning and fallback behaviour.
9. Invalid calibration files produce configuration errors.
10. Incompatible candidate formulations are detected.
11. Calibration is initialized once and reused.
12. Disabling calibration reproduces the uncalibrated R4 regression predictions.

## 7. Release Validation

Separate two validation targets:

**Uncalibrated compatibility**

Verify that the release implementation reproduces the frozen R4 routing predictions with calibration disabled.

**Calibrated behaviour**

Verify that calibration loads automatically and that the LLM output transformation matches the existing calibration implementation.

Do not reuse the R4 accuracy figures as measured calibrated accuracy.

Do not retune calibration parameters on the R4 held-out evaluation partition.

## Acceptance Criteria

- `models/calibration.json` is the default calibration configuration.
- Valid, compatible calibration is loaded and enabled automatically.
- Existing calibration mathematics are reused.
- Task-specific parameters are respected.
- kNN-5 voting is not incorrectly calibrated using LLM parameters.
- Zero-shot fallback receives the appropriate task-specific calibration.
- Missing and invalid calibration files are handled explicitly.
- Candidate formulation incompatibilities are never silently ignored.
- Production routing remains unchanged.
- The release candidate passes both calibrated and uncalibrated regression tests.
