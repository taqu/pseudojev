# Task: Implement S1 — Letter-Based Baseline for `score`

## Objective

Implement and evaluate a letter-based baseline for the `score` primitive.

S1 should preserve the exact same ordinal semantics and score ordering as S0, while replacing digit candidate tokens:

```text
0
1
2
3
...
```

with neutral letter candidate tokens:

```text
A
B
C
D
...
```

The purpose is to isolate one question:

> Does replacing digit candidate tokens with neutral letter tokens improve score quality by reducing digit-token bias, while preserving ordinal semantics?

Do not introduce rotation in S1.

Do not add few-shot examples.

Do not change unrelated prompt wording or model configuration.

---

# Experimental relationship to S0

S0:

```text
semantic level 0 -> "0"
semantic level 1 -> "1"
semantic level 2 -> "2"
semantic level 3 -> "3"
```

S1:

```text
semantic level 0 -> "A"
semantic level 1 -> "B"
semantic level 2 -> "C"
semantic level 3 -> "D"
```

Everything else should remain as close as possible to S0.

The primary experimental variable is:

```text
candidate representation:
digits -> letters
```

---

# Core invariant

The ordinal semantic order must remain unchanged.

For four score levels:

```text
semantic level 0 < semantic level 1 < semantic level 2 < semantic level 3
```

Prompt display order must remain:

```text
level 0
level 1
level 2
level 3
```

Only the candidate output token changes.

Correct S1 mapping:

```text
A -> semantic level 0
B -> semantic level 1
C -> semantic level 2
D -> semantic level 3
```

Do not reorder semantic levels.

The S0 vs S1 comparison must isolate candidate representation as much as possible.

If not:

- identify the offending label;
- do not silently fall back to digits.

Record the token IDs used by S1.

# Semantic interpretation

Even though candidates are letters, score semantics remain numeric ordinal levels.

For example:

```text
A -> level 0
B -> level 1
C -> level 2
D -> level 3
```

Expected score must still be:

```text
expected_score =
    sum_i i * P(level_i)
```

Do not compute expected score from:

```text
ASCII code
candidate position without semantic metadata
letter identity
```

Use explicit semantic level mapping.

# Signed ordinal margin

Use the same S0 definition.

For labeled sample:

```text
L_gt =
    semantic logit for ground-truth level

L_best_wrong =
    maximum semantic logit among all incorrect levels

signed_margin =
    L_gt - L_best_wrong
```

Letter candidate labels must first be interpreted as semantic levels.

Do not compute margin in raw candidate-letter identity space without semantic mapping.

# Calibration

If score calibration is already enabled, use the same calibration policy as S0.

For a clean S0/S1 formulation comparison:

- either use raw metrics for both;
- or independently fit valid score calibration artifacts using the same tuning protocol.

Do not reuse an S0 calibration artifact blindly for S1 if candidate-token representation is part of calibration compatibility.

Changing:

```text

```

changes candidate-token priors and may invalidate:

```text

prior alpha
temperature assumptions
```

Treat S1 as a distinct prompt/candidate configuration.

# Example interpretation

Suppose:

```text
S0:
accuracy = 0.60
MAE = 0.72
expected-score MAE = 0.61
mean signed margin = 0.4

S1:
accuracy = 0.60
MAE = 0.58
expected-score MAE = 0.49
mean signed margin = 0.9
```

S1 should be considered meaningfully better even though exact accuracy did not change.

Conversely, if accuracy rises but MAE worsens significantly, report the tradeoff rather than calling S1 unambiguously better.

S1 is complete when:

1. Score candidate labels use letters.
2. Ordinal semantic order remains unchanged.
3. Letters map explicitly to semantic levels.
4. All letter labels are validated as unique single tokens.
5. Expected score remains semantic-level based.
6. Existing S0 metrics are reused unchanged.
7. Candidate prior diagnostics are available.
8. One inference evaluation is used per item.
9. Easy/original/hard results are reproducible.
10. S0 vs S1 per-example comparison is generated.
11. No rotation behavior is introduced.
