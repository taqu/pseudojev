# S1 — letter-label baseline for `score`

S1 differs from [S0](s0.md) in one variable: the candidate representation. Digit labels
(`0, 1, 2, ...`) are replaced with letter labels (`A, B, C, ...`). The semantic order, display
order, prompt wording, layout, answer anchor, model and data are all the same as S0. There is
one evaluation per item and no rotation.

## Configuration

| item | S0 | S1 |
|---|---|---|
| command | `pjev run --calibration ""` | `pjev run --scheme letters --calibration ""` |
| candidate scheme | `natural` (digits) | `letters` |
| level i → label | `"i"` | `char('A' + i)` |
| layout / anchor / wording | auto (state-last) / `ANSWER_ANCHOR` / unchanged | same |
| prior correction | off | off |
| calibration | none (T = 1) | none (T = 1) |
| evaluations per item | 1 | 1 |

S1 uses the existing `Scheme::LETTERS` label assignment (`PromptStrategy::assign_labels`). For
`score`, the only thing it changes is the label text. `test_score_s1` checks that the S1 prompt
equals the S0 prompt with only the option labels and the `Reply with exactly one of ...` list
replaced.

**Calibration policy.** `models/calibration.json` was fitted for the digit scheme
(`candidate_scheme: natural`), so it is not reused for letters. Both S0 and S1 are compared at
`T = 1`. `pjev run` now checks the artifact against the run's formulation and records the
result under `calibration` in the output JSON. With the default artifact and
`--scheme letters` it warns:
`candidate_scheme mismatch (artifact=natural current=letters); prior_correction mismatch`.
The same artifact also flags `prior_correction mismatch` for the default S0 run, because it was
fitted with prior correction on.

## Mapping and tokens (bonsai.gguf)

| level | S0 label → id | S1 label → id | S1 `" X"` | S1 `"\nX"` |
|---:|---|---|---|---|
| 0 | `0` → 15 | `A` → 32 | 362 (single token) | 198 32 |
| 1 | `1` → 16 | `B` → 33 | 425 (single token) | 198 33 |
| 2 | `2` → 17 | `C` → 34 | | 198 34 |
| 3 | `3` → 18 | `D` → 35 | | 198 35 |
| 4 | `4` → 19 | `E` → 36 | | 198 36 |

- All letters are single, unique tokens. The engine refuses duplicate or multi-token labels and
  names them, for example `"B" (duplicate token id 65)` or `"C" (2 tokens)`. The letters scheme
  never falls back to digits, and does not even require digit tokens.
- Unlike digits, a **space-prefixed letter is its own token** (`" A"` = 362). The anchor ends in
  `"\n\n"`, and `anchor + "A"` tokenizes to anchor tokens `+ [32]`
  (`separate_token_after_anchor`), so the extracted token is the one the context produces.
  Probability the model puts on `" A"` falls outside the restricted softmax. The same is true
  for digits, which have no merged space form, so it does not bias the S0/S1 comparison in the
  anchor context.
- The mapping is explicit in every result: `score_candidates[].label_to_level` (label, level,
  token id), and per item `labels`, `levels`, `token_ids` and `selected_label`. Expected score
  uses `levels`, never the label text.

### Content-free priors

| levels | S0 digits (0, 1, 2, ...) | S1 letters (A, B, C, ...) |
|---:|---|---|
| 4 | −1.563, −3.179, −3.272, −5.240 | 2.170, −0.443, 0.402, −1.067 |
| 5 | −0.093, −2.148, −2.577, −4.448, −2.605 | 2.174, −0.407, 0.518, −1.395, −4.040 |

Both schemes favor the first label. With 4 levels the spread is 3.68 for digits (0 vs 3) and
3.24 for letters (A vs D). The digit prior falls monotonically with the level, which is an
ordinal-shaped bias. The letter prior is not monotonic (C > B).

## Reproduce

```sh
for s in easy original hard; do
  bin/pjev.exe run --input results/measure/s0/score_$s.jsonl --calibration "" --output results/measure/s1/s0raw_$s.json
  bin/pjev.exe run --input results/measure/s0/score_$s.jsonl --scheme letters --calibration "" --output results/measure/s1/s1raw_$s.json
done
uv run scripts/compare_results.py --primitive score --baseline-label "S0 digits" \
    --baseline "results/measure/s1/s0raw_{split}.json" \
    --target "S1 letters=results/measure/s1/s1raw_{split}.json" \
    --verify --output results/measure/s1/report_s0_vs_s1.md
```

Reruns produce bit-identical logits. The data is the same score items as S0: easy 0, original
12, hard 6.
